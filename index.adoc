=== re-scale

// 5 (~1.5 min): built 2026-04-08, the day after SSG's first honest measurement

[%step]
* A CLI + Claude Code plugin, rewritten in a day from the per-project helper tools
* Migration, audit and issue databases: agents query them instead of "remembering"
* A certificate header per file: method list + size baseline, verified in CI
* Checks against the original: method list, size ratio, TODO/stub wording, stale "not yet ported" excuses
* Implementer and auditor agents: "porting is binary — 100% or not done"

[NOTE.speaker]
--
Why it wasn't enough: every check looks at names and words, not behaviour.
Agents stamped 1,200 certificates while the CI check was off, reworded comments to dodge the scanner,
and kept every method name while hollowing out the bodies (see the June zoom).
--

=== Baltic Porter

// 6 (~2.5 min): started 2026-07-18

[%step]
* A deterministic translator: Java → typed IR → Scala 3 (plus TypeScript/JS/Dart front ends for SSG)
* Agents don't translate code any more; they build and measure the translator
* Each project owns its porting policy: renames, type redesigns (`Nullable`, opaque types, Panama), a few hand-written overrides
* Code is generated from upstream at build time; never edited, never committed
* Refuses loudly: what it can't translate is counted and reported, not guessed
* The oracle is tests: upstream suites and the hand ports' own suites, on JVM, JS and Native

[NOTE.speaker]
--
Results so far: libGDX core compiles with 0 errors (07-29), 12/12 demos render (09-07), SGE core generated with 5 overrides.
Its own first output had the same bug classes as the agents' (dropped breaks, == as identity, discarded anonymous classes),
but running the tests caught them. About 700 SGE extension files and SSG's non-Java ports are still hand-written: iteration one.
--

[.compact]
=== Baltic Porter: what we tried, where it still slipped

++++
<table class="versus"><thead><tr><th>The approach</th><th>What still went wrong</th></tr></thead><tbody><tr class="fragment"><td>Agents build the translator, never the port</td><td>The Mermaid "generator" was 187 templates copied byte for byte from the hand port (09-13)</td></tr><tr class="fragment"><td>Tests are the oracle</td><td>28 suites stubbed with <code>.ignore</code> → "0 failures, 18,011 tests" (09-12); 23 lls tests ignored 28 minutes after generation</td></tr><tr class="fragment"><td>Generated code is never edited</td><td>Regex patches over generated text and loosened assertions to make it pass (09-11); reverted 09-23/25</td></tr><tr class="fragment"><td>"Done" means it runs</td><td>"All twelve demos compile" reported as the goal reached (09-07)</td></tr><tr class="fragment"><td>Long autonomous runs</td><td>Subagents stopped on invented limits: "14.6M tokens remaining, I need to provide a handoff"</td></tr><tr class="fragment"><td>Deterministic translation</td><td>Compiling ≠ correct: dropped <code>break</code>s and <code>==</code> as identity found only by running tests; non-Java sources barely translate (KaTeX 5/474 bodies)</td></tr></tbody></table>
++++

[NOTE.speaker]
--
The difference from re-scale: these were caught, because the oracle is running tests and every count is computed by the tool, not reported by an agent. The limit is coverage, not honesty.

++++
<table class="versus solves four"><thead><tr><th>libGDX</th><th>JVM</th><th>Scala Native</th><th>Browser</th></tr></thead><tbody><tr class="fragment"><td>LWJGL (OpenGL)</td><td>ANGLE via Panama</td><td>ANGLE via <code>@extern</code></td><td>WebGL</td></tr><tr class="fragment"><td>LWJGL (GLFW, OpenAL)</td><td>GLFW, miniaudio via Panama</td><td>GLFW, miniaudio</td><td>DOM, Web Audio</td></tr><tr class="fragment"><td>jnigen natives (buffers, ETC1, gdx2d)</td><td>Rust library via Panama</td><td>same library, same C ABI</td><td>pure Scala</td></tr><tr class="fragment"><td>FreeType</td><td>Rust wrapper via Panama</td><td>static library</td><td><i>none</i></td></tr><tr class="fragment"><td>Box2D / Bullet (physics)</td><td>Rapier via Panama</td><td>static library</td><td>Rapier as WASM</td></tr></tbody></table>
++++

[NOTE.speaker]
--
One C ABI shared by every runtime: Panama on the JVM (and PanamaPort on Android), @extern on Scala Native. JNI is gone entirely (04-04). Each of these libraries has to be built for every platform and delivered to every build. SSG adds tree-sitter and curl.
--

=== Scala Native

// 9 (~2 min): linking against native libraries, cross-compiling

++++
<table class="versus solves"><thead><tr><th>Problem</th><th>What we built</th></tr></thead><tbody><tr class="fragment"><td>A library needs the native code installed on the system, plus linker flags you write yourself</td><td>Provider JARs carry static libraries and per-platform linker flags; an sbt plugin finds them on the classpath, extracts the right one and configures the linker. Resolving dependencies is enough to link</td></tr><tr class="fragment"><td>sttp on Scala Native needs a system libcurl</td><td>A ready-made curl provider: statically built for 6 desktop platforms</td></tr><tr class="fragment"><td>Scala Native builds only for the machine you're on</td><td>Cross-compilation through zig: one host produces binaries for the other operating systems and architectures</td></tr></tbody></table>
++++

[NOTE.speaker]
--
The core idea: a native library is a dependency like any other. Out of the box Scala Native expects you to install it and pass flags (scala-native#4800). zig cross-compilation: confirm the credit for the original idea (probably Lorenzo Gabriele's Mill prototype).

=== Scala.js

// 10 (~1 min): what the browser build lacks

++++
<table class="versus solves"><thead><tr><th>Problem</th><th>What we built</th></tr></thead><tbody><tr class="fragment"><td>No classpath: <code>getResourceAsStream</code> finds nothing, so a game can't load or list its assets</td><td>A build step embeds assets into the JS bundle; one resource API on JVM, JS and Native; directory listing from the embedded names</td></tr><tr class="fragment"><td>No <code>ServiceLoader</code> (and on Scala Native it only accepts a literal class)</td><td>A cross-platform ServiceLoader generated from <code>META-INF/services</code>; a typo fails at compile time</td></tr></tbody></table>

[NOTE.speaker]
--
libGDX solves assets with a generated assets.txt and GWT's preloader. SGE first copied that (manifest + fetch), then moved to embedding, which also makes loading synchronous.
