Talk plan (draft, 25 of 30 minutes)

Thesis: automatic porting of libraries is not solved. It needs constant attention and very careful verification, and even then the first result is a first iteration, not the intended port.

From missing APIs to hollow method bodies

Step 1 · files

The migration DBs said "ported"

Nearly every file was "done" from the start (sge 539/605 on 02-27, sass 283/283 on 04-06). The first phantom port appeared on 03-31: a file marked ported that did not exist. By 06-22, 28 such rows had been corrected in ssg-md.

Step 2 · methods & classes

Method comparison showed whole APIs missing

04-07: Environment.scala missing 27 methods. 04-10: sass 186 of ~515 methods missing; gltf exporters package (10 files) gone; Box2D 400+ files → 8. 04-18: 5,956 raw missing members and 12 Java files never ported.

Step 3 · bodies

With every method present, the insides were simplified

04-10: 25.8% of sass methods "SIMPLIFIED (exists but cuts corners)". 04-18: "Prior audits only checked method-set names". 06-10: dropped breaks, inverted guards, dead stores, discarded write-backs, options accepted and ignored.

Why enforcing the API could not catch it

  • The certificate check (Covenant verify) compares method names only. The recorded baseline line count is parsed but never checked.
  • The baseline came from the Scala file itself at stamping time, not from upstream. Stamping ~1,200 sge files (04-20) and 964 ssg files (04-26) froze whatever was there, gaps included. From then on the check only blocked further deletions.
  • The 70% body-size floor ("the gate that prevents one-line shim ports", 04-07) exists only in the strict comparison. CI never ran it, it merges overloads by name, and a body at 70% of the tokens can still have lost a branch.
  • The audit DB recorded "All methods present" as the audit. SpriteCache and GlyphLayout both carry that verdict and both were broken at the algorithm level.

About "wrap up as fast as possible". No surviving record shows Anthropic or Claude Code telling a porting agent to finish quickly. From 09-05/06, after credit pressure: "BUDGET small … STOP at the first landing state".

LLS: Low Level Scala

What it is and where it came from

A zero-dependency Scala 3 library for JVM, JS and Native that avoids allocation, boxing and reflection.

  • 2026-05-14 (3d0fc4a): 16 files extracted from SGE. Nullable, MkArray, Eval and Resource, plus libGDX's DynamicArray, ObjectMap/Set, OrderedMap/Set, ArrayMap, Sort, TimSort, Select and MathUtils.
  • Same day: boxing removed via a sealed MkArray hierarchy (4c31094). New zero-allocation ArrayView (eb0ccfc, "zipWithIndex foreach 12.6x faster"). JMH benchmarks added.
  • 05-15: SGE migrates (85b0a8a3, 884 files, −10k lines). 05-16: SSG adopts it.
  • Buffers and natives were not extracted; they stayed in SGE and multiarch-scala.

Releases

  • 0.1.0 (05-16): first release, on sbt-kubuszok from day one.
  • 0.2.0 (06-20): sbt 2. Fixes ISS-686, a ClassCastException in inline iteration that blocked every SGE FrameBuffer.
  • 0.3.0 (07-07): lls-io, planned in the Fable window. ssg and sge never adopted it.
  • Since then, snapshots only.

Baltic Porter era

  • 09-05: "lls FIRST" becomes the base rung of the libGDX ladder.
  • 09-11 (6cc2226): −5,385 hand-written lines; libGDX added as a submodule and lls generated at build time. Within 28 minutes an agent ignored 23 tests to reach "green".
  • 09-18/19: bytecode tests showed all four README "zero-overhead" claims failing; fixed or toned down (aa86c5c). JMH found traversals up to 34x slower; fixed.
  • 09-19: the 23 ignores removed; 570 → 593 passing. Lesson recorded: an inline member compiles into the caller, so SGE broke against the new lls.
  • 09-21: the porting policy moves into lls as lls-port.

Tooling gaps it hit

LLS has no native code, so its gaps went to sbt-kubuszok, Baltic Porter and local build workarounds rather than to multiarch-scala:

  • sbt 2's cached test passes with zero tests run.
  • scoverage with forked tests crashes.
  • The thin-client server keeps a stale environment.
  • A test-interface eviction on Scala Native.

  • Scala.js compiles a labelled boundary.break across nested loops so it exits only the inner loop, which broke TimSort.
  • Scala Native on Windows drops UNC path prefixes.
  • Scala 3.9 is blocked because the 3.8.4 meta-build can't read 3.9 TASTy.

Gaps in Scala tooling that forced multiarch-scala

  • Scala Native has no way to ship native libraries through Maven (scala-native#4800). Answer: NativeProviderPlugin + sn-provider.json.
  • No cross-compilation in Scala Native. Answer: zig-based MultiArchNativeReleasePlugin.
  • The JVM packager builds only for the host platform. Answer: MultiArchJvmReleasePlugin (jlink + Roast, 6 platforms).
  • No standard native loader on the JVM. Answer: NativeLibLoader + pnm-provider.json.
  • Panama differs between JDK 22+ and Android. Answer: multiarch-panama-api / -jdk.
  • No maintained sbt Android plugin. Answer: AndroidPlugin.
  • Scala.js has no resources or ServiceLoader. Answer: multiarch-resources, multiarch-serviceloader.
  • Two JARs bundling the same .so collide silently. Answer: manifest v2 collision checks.
  • Every cross-built library repeats the same build boilerplate. Answer: sbt-kubuszok.
